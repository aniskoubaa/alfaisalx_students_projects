Connect over Wi-Fi

The robot and this computer must be on the same network to talk. There are three ways to do that. The boxes below show where you are now. Pick the way that fits, and follow its steps.

This computer

The robot

A. Robot’s own Wi-Fi (hotspot)

★ You are here

Use this when there is no other network, for example when you are away from your usual Wi-Fi. If the robot cannot find a saved network, it makes its own Wi-Fi called Turtlebot4.

  1. Join the Turtlebot4 network on this computer. The password is in the TurtleBot 4 manual, or ask whoever set up the robot.
  2. Press Discover, then Connect. The robot is at 10.42.0.1.

Heads up: while this computer is on the robot’s hotspot it has no internet, unless it has a second connection.

B. Join a Wi-Fi network

★ You are here

Best for daily work: robot and computer both join the same Wi-Fi (home, school or office). You teach the robot the network once. Works with a normal Wi-Fi password (WPA or WPA2 personal).

This computer is on: (unknown)

You need to be connected to the robot already (cable or hotspot). The robot keeps its own hotspot as a backup. Afterwards press Discover: Studio remembers the robot’s address, or read it on the robot’s little display.

Not supported: networks with a login web page, with a username and password (802.1X / WPA2-Enterprise), open networks and WPA3-only networks.

C. Ethernet cable

★ You are here

Always works and needs no settings. Plug the cable between this computer and the robot, wait a few seconds, then press Discover and Connect. The robot’s cable address is 192.168.185.3.

A cable is also the way to set up option B the first time.

  • Robot not found on Wi-Fi: read its address on the robot’s display and type it into the address box on the Dashboard.
  • turtlebot4.local often fails on shared Wi-Fi, so Studio does not rely on it.

How robot code works (short guide for beginners)
  • A robot program is a small Python file. It runs on the robot, in a folder called ~/robot_code.
  • In ROS 2 a program is called a node. Nodes talk through topics.
  • To read a sensor, subscribe to a topic: /odom is where the robot thinks it is, /scan is the lidar, /battery_state the battery, /dock_status whether it sits on the dock.
  • To move, publish a speed on /cmd_vel. It is a TwistStamped message: linear.x is metres per second forward, angular.z is radians per second turning left. Send it 10 to 20 times per second.
  • Always finish by publishing zeros. Otherwise the robot may keep rolling. The templates already do this for you.
  • The robot cannot drive while docked. Undock first (Dashboard).
  • Safety: the E-STOP button works at any time. In this editor, Esc and Space just type or do nothing, so use the button or Ctrl+Shift+E.
  • Run a file here with Save & Run, or in a terminal: python3 my_file.py.
  • Start from New program: each template has the safety parts built in (speed limits, time limit, stop on obstacles).
