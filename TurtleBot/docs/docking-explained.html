TurtleBot 4 · Create 3 base · docking

How docking works

The dock sends out infrared (IR) signals. The robot listens for them with two IR sensors, finds the line in front of the dock, and drives in slowly until its charging contacts touch. This page shows the steps, lets you place a simplified robot anywhere and press Dock, and gives the commands to undock and dock the real one.

Verified on this robot undock (2026-10-04), dock (2026-10-03) Not yet run ros2 topic echo /ir_opcode Not documented by iRobot the exact steering algorithm
01

What happens when you press dock

The /dock action runs four stages. The official Create 3 text says the robot "will first search for the dock in its immediate surroundings", then "will align with the dock and carefully drive onto it". The split into four stages below follows that text; the names are this page's.

  1. waiting

    Search

    The robot looks for the dock's infrared signals nearby.

  2. waiting

    Align

    It gets onto the centre line in front of the dock and faces it.

  3. waiting

    Approach

    It drives in slowly.

  4. waiting

    Contact

    The charging contacts touch. /dock_status shows is_docked: true.

Undocking is shorter. Official text: "The robot will move backward out of the dock and then it will rotate 180 degrees."

  1. waiting

    Back out

    Move backward out of the dock.

  2. waiting

    Rotate 180 degrees

    Turn around so the robot faces away from the dock.

These boxes light up in the simulator below while it runs. If you cannot watch an animation, use the Step button there.

The codes and the sensors

ConstantValueIn this drawing
CODE_IR_BUOY_RED168Only the buoy A zone
CODE_IR_BUOY_GREEN164Only the buoy B zone
CODE_IR_BUOY_BOTH172Both beams overlap: the centre line in front of the dock
CODE_IR_FORCE_FIELD161Very close to the dock (short-range force field)
SENSOR_OMNI0All-round receiver. Shown when the robot is not facing the dock
SENSOR_DIRECTIONAL_FRONT1Front-facing receiver. Shown when the robot points within 30 degrees of the dock

The constants and sensor numbers are from the official irobot_create_msgs/msg/IrOpcode message. The robot publishes what its two IR sensors detect on /ir_opcode. That the "red" and "green" buoy beams mark the two sides and "both" is where they overlap is the usual reading of the codes in iRobot docks; the assignment of A to red and B to green above is only this page's naming. The rule for which sensor "sees" what is also this page's simplification.

03

Undocking

Undock starts on the dock. The robot backs out, then rotates 180 degrees so it faces away. Press the button to play it in the simulator above (the robot is put on the dock first).

  • On the TurtleBot 4 the lidar is switched off while the robot is on the dock (power saving). It switches back on a few seconds after undocking. The simulator shows this in the Lidar line. The "few seconds" in the simulator (3 s) is a placeholder.
  • The back-out distance is not given in the official text; the simulator uses 35 cm as an illustration.
  • Undock fails if the robot is already undocked (verified 2026-10-04: the action needs a docked robot).
04

Do it yourself

Run these on the robot (SSH in first, see HOW-TO-CONNECT.md). Over a plain SSH login they work as they are; in a script or non-login shell start with source /etc/turtlebot4/setup.bash. ROS commands take 30 to 60 seconds to start on the Pi, so be patient.

Undock verified 2026-10-04
ros2 action send_goal /undock irobot_create_msgs/action/Undock "{}"
Dock verified 2026-10-03
ros2 action send_goal /dock irobot_create_msgs/action/Dock "{}"
Watch the dock status seen on this robot
ros2 topic echo --once /dock_status

It prints dock_visible and is_docked, the two fields shown in the simulator.

Watch the IR codes not yet run on this robot
ros2 topic echo /ir_opcode

Expect messages with an opcode (161, 164, 168 or 172 near the dock) and the sensor that saw it, from the official message definition. Not tried on this robot yet, so the output has not been checked.

Run it detached, so a Wi-Fi drop cannot cancel it
setsid nohup ros2 action send_goal /dock irobot_create_msgs/action/Dock "{}" > ~/robot_code/dock.log 2>&1 &
cat ~/robot_code/dock.log

This is the form from HOW-TO-CONNECT.md. The same form for undock (/undock and undock.log) was not run this way yet. The log shows the result when the action ends.

Tips

  • The robot can drop off the Wi-Fi while it moves (seen 2026-10-03, when SSH dropped as docking started). A detached run keeps going; an attached one may be cancelled.
  • Finish your runs near the dock: docking fails if the robot is too far away.
  • The dock must be plugged in. Without power it sends no signal and the robot cannot find it.
  • Keep the area in front of the dock clear, and keep a person next to the robot while it moves (lab rule: 1 m clear around it).
  • Stopping an attached run: Ctrl+C. The lab script motion_test.sh shows undock, a short drive, and dock in one run.

Troubleshooting

What you seeLikely reasonWhat to do
Undock failsThe robot is already undocked.Run ros2 topic echo --once /dock_status. If is_docked: false, skip the undock.
Dock failsThe robot is too far from the dock. The official docs say docking fails then.Move it back in front of the dock and try again. The maximum distance is not stated in the docs used here, so start close.
Dock failsThe dock is unplugged, so it sends no signal and the robot cannot detect it.Check the dock's power plug, then try again.
Dock failsThe robot is already docked.Check /dock_status. is_docked: true means nothing more to do.
The robot stopped half way and the SSH session diedThe Wi-Fi dropped and the attached action was cancelled.Reconnect and run dock detached (see above). Check the log file.
No /scan after dockingExpected: the lidar is off while docked (power saving).Nothing. Undock and wait a few seconds for it to start again.
Still no /scan a while after undockingNot caused by docking.See Lidar diagnosis.

What is not documented

  • The exact steering algorithm of the Create 3 docking. The simulator is this page's own simplification, built from the documented signals and the documented steps.
  • Which side the two buoy beams cover, their real range and angles, and the force-field distance.
  • The maximum starting distance for a successful dock, and the back-out distance of the undock.
  • The contents of /ir_opcode messages on this robot (not yet run).
  • In the simulator, "is_docked" is true when the robot sits in the dock's contact position. The real robot decides this from its charging contacts.
TurtleBot 4 lab documentation. Official statements are quoted from the iRobot Create 3 documentation as recorded in the lab notes. Everything animated on this page is an illustration.
