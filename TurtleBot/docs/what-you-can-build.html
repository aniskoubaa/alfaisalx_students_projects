What students can learn here

The lab robot is a real ROS 2 machine: a Raspberry Pi 4 on an iRobot Create 3 base, with a lidar, wheel odometry, a dock and a light ring. You write short Python programs that read its topics and send it velocity commands. Along the way you learn how ROS 2 topics and actions work, how to drive in a closed loop on odometry, how to use a lidar to stop safely, and how to test and document robot code. The levels get harder one step at a time. Start at level 1 unless you already know ROS 2.

Note: much of this robot's code was tested only off the robot (simulator and unit tests). Every card says which part has run on the real robot and which part has not. The base also pauses its /odom data now and then, so every moving program waits about 20 to 25 s before its first move (why).

Safety first

Before any program that moves the robot, go through the safety checklist. In short:

  • About 1 m of clear floor all round. No cables, bags, feet, stairs or drop-offs.
  • The robot is off the dock, and a person stands next to it for the whole run.
  • You know how to stop it (Ctrl+C, touch ~/STOP, or E-STOP in TurtleBot Studio).
  • Speed stays at or below 0.15 m/s. Do a --dry-run first.

Programs that only read sensors are safe to run at any time.

  1. LEVEL 1

    Hello robot and reading sensors

    Suggested

    Run your first program on the robot and see live data: battery, dock state, position, topic rates.

    Skills
    Logging in with SSH, running Python on the robot, what a ROS 2 topic is, reading /odom, /battery_state and /dock_status.
    Sensors
    Odometry, dock state, battery. Works on the dock.
    Difficulty, time
    Easy. About 1 hour (rough estimate, not measured).
    Python needed
    None to run it; a little to change it.
    • my_first_program.pyTested on the robotStudio template. Prints battery, dock state and position for 10 s. Ran on the robot on 2026-10-24.
    • hello_robot.pyNo result recordedText on the display and a green light ring for 5 s. A copy is on the robot, but the docs record no run.
    • sensor_report.pyOffline onlyTopic rates, gaps and battery. Not yet run on the robot (TB-23).
    • lightring_status.pyOffline onlyShows the battery level on the light ring.

    First command (on the robot, after ssh ubuntu@turtlebot4.local)

    python3 hello_robot.py

    Connection steps: Do it yourself.

  2. LEVEL 2

    Moving safely: undock, drive, dock, stop

    Suggested

    Make the robot leave the dock, move a short distance, come back, and stop on command.

    Skills
    ROS 2 actions (/undock, /dock), publishing velocity, the safety checklist, stop methods, running programs detached so a Wi-Fi drop does not cancel them.
    Sensors
    Dock state, odometry. The lidar clearance check is used when the lidar is running.
    Difficulty, time
    Medium. An afternoon (rough estimate, not measured).
    Python needed
    None for the shell commands; a little to read the programs.
    • motion_test.shTested on the robotUndock, clearance check, 20 cm forward, 360 degree spin, dock. Run on 2026-10-03; the forward drive was skipped because the lidar was not detected then (test results).
    • Undock and dock commandsTested on the robotThrough TurtleBot Studio on 2026-10-24 (Studio README). The commands are in examples/README.md.
    • drive_test.pyNo result recordedForward 20 cm at 0.1 m/s. It has no obstacle check, so keep 1 m clear.

    First command (on the robot, detached so a Wi-Fi drop cannot cancel it)

    setsid nohup ros2 action send_goal /undock irobot_create_msgs/action/Undock "{}" > ~/robot_code/undock.log 2>&1 &

    Check with cat ~/robot_code/undock.log and look for SUCCEEDED. It can take up to a minute.

  3. LEVEL 3

    Closed-loop shapes on odometry

    Suggested

    Drive a square, triangle, circle or spin by measuring how far the wheels say you moved, and compare the plan with the result.

    Skills
    Closed-loop control, /odom and /cmd_vel, planning a path as segments, why odometry drifts, dry runs, abort rules (stale data, bump, stall, timeout).
    Sensors
    Odometry. The lidar is used only as an obstacle stop.
    Difficulty, time
    Medium. An afternoon (rough estimate, not measured).
    Python needed
    A little. The Studio templates are short and good to edit.
    • motion_shapes.pyTested on the robotOn 2026-10-04: square, rotate, back_and_forth and triangle completed, with odometry end errors of 1.0 cm or less (odometry only, not floor measurements). The figure eight aborted on a 2.0 s odometry gap and is still open (TB-16).
    • spin_in_place.pyTested on the robotStudio template. Turned 359 degrees on 2026-10-24. An earlier run was aborted by an odometry gap, as designed.
    • drive_circle.pyTested on the robotStudio template. Drove the lap on 2026-10-24. Its closure figure is not valid because the robot crossed the dock edge and was moved by hand.
    • drive_forward_and_back.pyOffline onlyStudio template. Simulator result only.
    • more_shapes.pyOffline onlyPolygon, star, circle, spiral, zigzag and a repeatability test. Not yet run on the robot (TB-23).

    First command (on the robot)

    cd ~/robot_code
python3 motion_shapes.py square --dry-run

    A dry run never moves the robot. Preview the motion in your browser first with the motion simulator, and read the program design.

  4. LEVEL 4

    Using the lidar

    Suggested

    Read the lidar, check the way ahead, draw a scan, and make the robot keep a distance or approach a wall.

    Skills
    The /scan topic, angles in the robot frame, nearest-object checks, a simple proportional controller, comparing lidar distance with odometry.
    Sensors
    Lidar, plus odometry for the moving programs. The lidar is off while the robot is docked.
    Difficulty, time
    Medium to hard. An afternoon (rough estimate, not measured).
    Python needed
    A little.
    • clearance_check.pyTested on the robotOne scan, nearest object within 30 degrees of straight ahead. On 2026-10-04 it exited 0 (clear) with the nearest object at 1.73 m. The lidar ran at 7.75 Hz off the dock.
    • scan_test.pyNo result recordedPrints the nearest distance until Ctrl+C. The 2026-10-04 check used ros2 topic commands instead.
    • read_lidar.pyOffline onlyStudio template that prints what the lidar sees.
    • lidar_snapshot.py and scan_plot_html.pyOffline onlySave a scan, then draw a polar plot on your own computer.
    • wall_approach.pyOffline onlyDrives slowly towards a wall to a target distance and prints odometry against lidar.
    • keep_distance.pyOffline onlyHolds 0.6 m to an object ahead, for at most 60 s.

    First command (on the robot, robot off the dock)

    python3 clearance_check.py

    Read the lidar guide first. Known issue: once the lidar motor did not restart after undocking and was started by hand (TB-24).

  5. LEVEL 5

    Combining sensors and behaviours

    Suggested

    Write your own program that uses more than one sensor, then measure how well it works: repeat a shape and log the error, or run a batch of tests.

    Skills
    Combining odometry, lidar and dock state in one node, logging to a file, repeatability measurements, writing a test plan and a short report.
    Sensors
    Odometry, lidar, dock state.
    Difficulty, time
    Hard. Several sessions (rough estimate, not measured).
    Python needed
    Comfortable.
    • more_shapes.py repeatabilityOffline onlyRuns a shape K times and prints the odometry error per loop.
    • campaign.shOffline onlyRuns a list of shape commands with a sensor report before and after. The robot campaign (TB-16) is still open.
    • health_check.pyOffline onlyRead-only health checklist. Robot run pending (TB-19).
    • Your own program, for example drive out and back with a lidar stopIdea, not yet triedStart from a Studio template in the Code tab.

    First command (dry run, moves nothing)

    python3 more_shapes.py repeatability --shape square --loops 3 --dry-run

    Copy the files to the robot first (how). As of 2026-10-10 only hello_robot.py to motion_shapes.py were on the robot.

  6. LEVEL 6

    Mapping and navigation

    Suggested

    Build a map of a room and send the robot to a goal on it.

    Skills
    What SLAM and a navigation stack do, ROS 2 over a network from a laptop, visualising a map, tuning.
    Sensors
    Lidar and odometry. The platform also has a camera; no program in this repo uses it.
    Difficulty, time
    Hard. Several sessions (rough estimate, not measured).
    Python needed
    Comfortable, plus patience with setup.
    • Mapping and navigationIdea, not yet triedThe TurtleBot 4 platform supports SLAM and navigation (see the official TurtleBot 4 user manual). It has not been tried on this robot, and the lab roadmap has no task for it yet.

    What to settle first

    • Steady /odom: the base still pauses its data (TB-25, open).
    • A dependable lidar after undocking (TB-24).
    • ROS 2 from a laptop over the campus network (TB-09, open).

    There is no first command yet. Talk to the lab maintainer before starting this level, so the work can be added to the roadmap.
