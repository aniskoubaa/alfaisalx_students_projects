TurtleBot 4 · Studio 2.1

Studio lab demo

From install to the front-panel delivery demo in eight steps: install, connect over campus Wi-Fi, map a room, plan a route, put it on the robot, start navigation and run the trip. Each step says what was verified on the real robot and what was not.

Robot TurtleBot 4, ROS 2 JazzyStudio 2.1Facts as of 2026-11-25

Safety first

  • Unplug the Ethernet cable before the robot moves. It must never drive with the cable plugged in.
  • A person stands next to the robot while it moves, with E-STOP in reach (top right of every Studio screen; Esc or Space too, not while typing in a box).
  • Keep about 1 m of clear floor. The lidar does not see glass: stop the robot before glass doors and glass rooms.
  • Battery above 40 % for a trip. Studio refuses to drive below 10 %.

Not verified yet. Mapping while driving, route upload, and a trip in the lab or on campus have not been done on the real robot. Stay beside the robot for all of them.

01

Steps

0 of 8 steps done
1

Install Studio

▸
  1. Download: Download page, or directly TurtleBotStudio-Setup-2.1.exe (Windows 10 and 11, 8.9 MB, no administrator rights).
  2. Open the file. If Windows says "Windows protected your PC", click More info, then Run anyway (the app is not signed by a company).
  3. Click Next, Install, Finish. You get TurtleBot Studio and TurtleBot Studio (simulated robot), a practice copy where nothing real moves.

macOS and Linux: INSTALL.md, option B. Not verified the 2.1 installer on a clean computer.

2

Connect over campus Wi-Fi

▸
  1. Switch the robot on. It joins the campus Wi-Fi Students by itself and shows its address on its screen (starts with 10.87.). The address can change: read it each time. Example 2026-11-25: 10.87.11.67.
  2. Put your laptop on the same network.
  3. Start Studio. On Overview press Discover, pick the robot, press Connect. If it is not listed, type the address from the robot's screen. turtlebot4.local sometimes fails on campus. See Find the robot.
  4. First time on a computer: run the setup wizard once (First connection). It uses the Ethernet cable and asks for the robot's password in a terminal window; see How to connect or ask the lab maintainer. Then unplug the cable.

Verified 2026-11-25 robot joined Students at boot; a laptop on Students reached it with no cable. Not verified the one-time key setup over Wi-Fi without the cable.

3

Look around Studio

▸

Spend two minutes on the screen tour below. You need Overview, Maps, Routes and Tools.

4

Map a room

▸

Needs: robot docked, no navigation program running, delivery package on the robot (it is). Detail: Maps and routes.

  1. Maps, press Start mapping. Wait for Mapping (6 to 10 s on 2026-11-14).
  2. Overview, press Undock, confirm. Check the robot is clear of the dock. Back to Maps.
  3. Drive slowly (drive panel armed, or the controller). Cable unplugged, person beside the robot.
  4. Close the loop: drive back along the same wall to where you started.
  5. Save map, type a name (letters, digits, hyphens, underscores), confirm (about 18 s).
  6. Dock the robot (Overview, Dock).
  7. Stop mapping and answer the question.

Starting mapping stops the robot's camera container until the next reboot. Check the map scale against one measured distance: if it is more than about 3 % short, map again.

Verified 2026-11-14 start, live map, save, stop, preview, download, rename, delete, with the robot docked. Not verified mapping while driving.

5

Plan a route on your computer

▸

Studio does not plan routes. Detail: delivery README section 8.

  1. In Maps download your saved map (a zip) and unzip it.
  2. Python 3.10 or newer and PyYAML: python -m pip install pyyaml (python3 on macOS and Linux).
  3. From the repository root: 
    python TurtleBot/delivery/tools/plan_route.py --map <your-map>.yaml --info
  4. Copy route_spec.example.yaml, replace the made-up numbers (dock pose, goal, glass keep-out lines), then: 
    python TurtleBot/delivery/tools/plan_route.py --map <your-map>.yaml --spec my_spec.yaml --out my_route
  5. Open my_route/preview.html and read every warning. The folder needs route.yaml, map.yaml, keepout_mask.yaml, speed_mask.yaml.
6

Put the route on the robot

▸
  1. Routes, Choose a route folder, pick my_route.
  2. Check Name on the robot (new name; current is reserved). Press Upload. Nothing moves.
  3. In Routes on the robot press Use this route in your row and confirm. Current route must show your name.

Important. The current route is home, a 1.1 m test route from a room at home. Change it before any trip in the lab. Use this route is refused while a trip or the navigation program runs.

Not verified route upload, and Use this route with a different route.

7

Start the navigation program

▸

Studio 2.1 cannot do this. It starts mapping and shows on Routes whether navigation is running, but a trip needs the navigation stack started from a terminal on the robot first (delivery README section 9).

  1. Robot on the dock, battery above 40 %.
  2. Open a terminal on the robot: Studio, Tools, the button for a terminal on the robot. Or ssh ubuntu@<address on the robot's screen> from your computer's terminal (needs the first-connection key or the password, see How to connect).
  3. On the robot (replace my_route): 
    bash ~/robot_code/delivery/robot/start_stack.sh nav --route-dir ~/robot_code/routes/my_route --dry-run
bash ~/robot_code/delivery/robot/start_stack.sh nav --route-dir ~/robot_code/routes/my_route
  4. Wait about 2 minutes, then: 
    grep -i "Managed nodes are active" ~/robot_code/logs/delivery/latest/stack.log | tail
    No line: run bash ~/robot_code/delivery/robot/stop_stack.sh and read the log.
  5. When finished: bash ~/robot_code/delivery/robot/stop_stack.sh.

Does the stack keep running if you close that terminal? to verify. Keep it open during the demo.

8

Run the demo from the front panel

▸

Cable unplugged, robot docked, navigation running, a person ready to walk behind the robot.

ButtonIn the menu
1Select the highlighted entry
2Back. During a trip it is Stop
3Up
4Down
  1. The first entry is >Go to food court when docked. Others: Dock, Undock, EStop, Wall Follow Left and Right, Power, Help, and Hello demo (a 20 s countdown that never moves).
  2. Select Go to food court (1), then answer 1 = Yes / 2 = No with 1. The first movement comes about 1 min 15 s later (measured at home, 2026-11-06).
  3. Walk behind the robot. Button 2 stops it at any time.
  4. At the food court: Food placed?, press 1 for Back to the lab.
  5. At the lab: Your food is here, press 1 for Done, thank you. The robot docks.

Verified at home 2026-11-06 a whole delivery on a 1.1 m route, Stop, Back to the lab, physical buttons. Not verified a trip on a lab or campus route; selecting Hello demo on the screen.

04

Troubleshooting finder

"Windows protected your PC"

Click More info, then Run anyway. The installer is not signed.

Discover finds nothing

Check the robot and the laptop are both on Students. Type the address from the robot's screen. See Find the robot.

turtlebot4.local does not work

Normal on campus at times. Use the address on the robot's screen.

"key not set up"

Run the setup wizard once on this computer: First connection.

The robot shows its own Wi-Fi Turtlebot4

It could not find Students. Join Turtlebot4 from your computer; the robot is at 10.42.0.1.

Start mapping is grey

A navigation program is running (stop it with stop_stack.sh) or the mapping scripts are missing (copy the delivery package with delivery/tools/deploy.py).

Driving is grey or refused

The robot is docked, e-stopped, starting or saving a map, a motion program runs, or the battery is under 10 %. Undock on Overview.

The map does not grow

The lidar motor is off while docked. Undock or start the lidar on Overview, then drive a little.

Upload says a file is missing

The four route files must sit directly in the folder, not in a subfolder. Run the planner again.

Use this route is grey

The route is incomplete, already current, or a trip or navigation program is running.

The screen says "Not on the map"

Navigation is not running. Do step 7 and wait about 2 minutes.

The screen says "No route saved"

The current route folder has no route.yaml. Make your route current (step 6).

The camera stopped after mapping

Known side effect of starting mapping. It comes back after the next reboot.

Anything else

Studio troubleshooting, or ask the lab maintainer. Tools, Show diagnostics makes a text to send.
